# 设置页左侧导航布局设计

## 背景

当前设置页 `src/routes/settings/+page.svelte` 使用纵向卡片布局，页面内依次展示外观设置和账号管理。随着设置项增加，这种结构会让页面变长，也不利于后续加入“通用”等更多设置分组。

本次优化将设置页调整为桌面应用常见的“左侧导航 + 右侧内容”设置中心布局。用户已确认采用“设置中心”方向，并要求保留“通用”分组，因为该分组马上会新增内容。

## 目标

1. 设置页改为左侧导航、右侧内容的双栏布局。
2. 左侧导航包含三个分组：通用、外观、账号管理。
3. 默认选中通用分组。
4. 右侧内容根据当前选中的分组切换展示。
5. 保留现有外观设置和账号管理功能。
6. 保留现有测试依赖的 `data-testid`，避免破坏已有 e2e 流程。
7. 窄屏时布局降级为顶部横向分段导航和单列内容区。

## 非目标

1. 不新增真实通用设置项。
2. 不调整主题、语言、账号删除等业务逻辑。
3. 不修改全局布局、侧边栏、状态栏或标题栏。
4. 不提交代码，除非用户另行明确要求。

## 信息架构

设置页只有一个路由 `/settings`，不新增子路由。页面内部使用局部状态保存当前选中分组。

分组定义：

- `general`：通用，默认选中。
- `appearance`：外观，承载主题切换和语言切换。
- `accounts`：账号管理，承载账号列表、删除错误提示和账号卡片。

## 布局设计

桌面布局：

```text
+------------------------------------------------------+
| 左侧设置导航                    | 右侧当前分组内容     |
|---------------------------------|----------------------|
| 返回按钮 设置                  | 标题 / 说明          |
|                                 |                      |
| 通用       [active]             | 分组内容             |
| 外观                            |                      |
| 账号管理                        |                      |
+------------------------------------------------------+
```

左侧导航区：

- 宽度保持稳定，约 220px 到 240px。
- 顶部包含返回按钮、设置图标和页面标题。
- 每个导航项使用图标加文字。
- 当前选中项使用主色背景或左侧强调线，并保证暗色主题可读。

右侧内容区：

- 占据剩余空间。
- 内部独立滚动。
- 内容宽度设置合理上限，避免控件在宽屏下过度拉伸。
- 继续使用项目现有的 `bg-card`、`border-border`、`bg-glass`、`text-muted-foreground` 等设计令牌。

窄屏布局：

- 左侧导航变为顶部横向分段导航。
- 内容区变为单列滚动。
- 返回按钮和标题仍然位于页面顶部。

## 分组内容

### 通用

通用分组作为默认页面展示。

本次只提供轻量占位内容：

- 标题：基础设置。
- 简短说明：用于承载应用级偏好设置。

该占位内容不是空状态，也不提示“敬请期待”，避免显得功能未完成。

### 外观

迁移现有外观设置内容：

- 主题切换：浅色、深色、跟随系统。
- 语言切换：中文、English。

保留现有主题按钮测试标识：

- `theme-light`
- `theme-dark`
- `theme-system`

### 账号管理

迁移现有账号管理内容：

- 删除错误提示。
- 账号列表。
- 空账号状态。
- 单个账号卡片和删除按钮。

保留现有账号卡片测试标识：

- `settings-account-card`

## 状态与交互

设置页内部新增局部状态：

- 初始值为 `general`。
- 点击左侧导航项时更新当前分组。
- 不写入 URL，也不持久化到本地存储。

现有状态管理保持不变：

- `i18n` 继续管理语言。
- `themeStore` 继续管理主题。
- `accountStore` 继续加载、展示和删除账号。

页面加载时仍执行 `accountStore.loadAccounts()`，确保进入账号管理分组时数据已可用。

## 可访问性

1. 左侧导航使用按钮语义，而不是纯 div。
2. 当前选中的导航按钮设置 `aria-current="page"` 或等价语义。
3. 图标按钮保留可理解的标题或可访问名称。
4. 键盘焦点状态沿用项目现有焦点样式。

## 测试计划

遵循测试优先：

1. 新增或更新设置页组件测试，先验证失败：
   - 默认显示通用分组。
   - 点击外观导航后，主题按钮可见。
   - 点击账号管理导航后，账号区域可见。
2. 修改设置页实现使测试通过。
3. 运行 Svelte 检查：
   - `rtk bun run check`
4. 运行相关前端测试：
   - `rtk bun run test:frontend`

若现有测试环境无法直接渲染路由页面，应优先调整测试组织方式，而不是跳过覆盖。

## 风险与约束

1. 页面文件已有较长注释和模板，改动时需要控制复杂度，避免单文件继续膨胀。
2. 现有 e2e 依赖多个 `data-testid`，实现时必须保留。
3. 窄屏布局需要避免导航项文字挤压或换行导致高度跳动。
4. 暗色主题下选中态不能只依赖浅色背景，需要确认对比度。

## 验收标准

1. 打开设置页默认显示通用分组。
2. 左侧导航显示通用、外观、账号管理。
3. 点击外观后，主题和语言设置可正常使用。
4. 点击账号管理后，账号列表、删除错误提示和账号卡片行为保持不变。
5. 现有主题 e2e 选择器不失效。
6. 前端检查和相关测试通过，或记录明确的环境性阻塞原因。
