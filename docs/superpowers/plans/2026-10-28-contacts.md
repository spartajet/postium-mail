# 联系人管理模块实施计划（Contacts）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 spec 实现联系人模块：自动收集/回填、CRUD/分组/合并、ContactsView + 写信自动补全、vCard/CSV 导入导出、CardDAV 双向同步。

**Architecture:** core 一等公民——SQLite 四张新表 + ContactService（同构 label_service）+ CoreApi 门面；自动收集挂接同步落库与发送成功两个路径；CardDAV 用 reqwest 自研轻量客户端（PROPFIND/REPORT/PUT/DELETE）+ 自研 vCard 解析器；UI 三栏 ContactsView + RecipientField 补全浮层。

**Tech Stack:** Rust（tokio + tokio-rusqlite + reqwest + wiremock[test]）、GPUI（gpui-kit 0.8 组件）。

**Spec:** `docs/superpowers/specs/2026-10-28-contacts-design.md`（本计划从 spec 出发，执行者须同时读 spec）

## Global Constraints

- 邮箱地址入库前一律 `to_lowercase()`；主邮箱唯一索引 `idx_contacts_email ON contacts(lower(email))`
- source 三态：`local | collected | dav`；`collected` 永不上推服务端
- e2e 离线模式（`CoreApi::init(dir, e2e=true, e2e_truth=false)`）下所有 CardDAV 方法短路返回空/Ok，不发起网络请求
- i18n 新词条必须同时加 `i18n_tables.rs` 的 ZH 与 EN 两节（存在 `zh_en_key_sets_identical` 测试）
- 每任务结束 `cargo test -p postium-core`（或 `-p postium-ui`）全绿 + `cargo build --workspace` 0 警告后提交
- UI 异步一律 `crate::runtime::spawn_tokio` + `cx.spawn` 消费，禁止 UI 线程 block_on
- 提交信息用中文，格式沿用仓库现状（`feat(contacts): ...`）

### Task 3: 收集管线 upsert_from_emails + backfill

**Files:** Modify `contact_repo.rs`

**Interfaces（追加）:**

```rust
pub struct IncomingContact { pub email: String, pub name: Option<String>, pub contacted_at: i64 }
/// 批量收集：命中→collected 条目 frequency+=1/时间推进；local|dav 条目只推进时间、name 为空才补；
/// 未命中→插入 source='collected'
pub async fn upsert_from_emails(db, items: &[IncomingContact]) -> Result<(), MailError>
/// 存量回填（幂等）：聚合 emails 三列；collected 条目 frequency 全量覆盖，其余只推进 last_contacted_at
pub async fn backfill_from_emails(db) -> Result<usize, MailError>
```

- [ ] **Step 1: 失败测试**——
  1) 同一 sender 三封（含大小写变体）→ frequency=3、name 补齐；再插 dav 条目（直接 SQL 置 source='dav', frequency=99）→ upsert 只推进时间、frequency 仍 99；
  2) 手动 `INSERT INTO emails(...)` 两行（sender=a@x / recipient 含 b@x,c@x）→ backfill 得 3 联系人；再跑一次 → collected 条目 frequency 不变（幂等）
- [ ] **Step 2: 失败** → **Step 3: 实现**——upsert 单事务逐条 `SELECT id,source,name FROM contacts WHERE lower(email)=?`；backfill 聚合 SQL（json_each 展开收/抄送；拼接前把 `;`→`,`、去空白、过滤空串）：

```sql
SELECT lower(addr) AS email, MAX(name) AS name, COUNT(*) AS freq, MAX(sent_at) AS last_at FROM (
  SELECT sender_email AS addr, COALESCE(sender_name,'') AS name, sent_at FROM emails WHERE is_deleted=0
  UNION ALL
  SELECT j.value AS addr, '' AS name, e.sent_at FROM emails e,
    json_each('['||replace(replace(e.recipient_emails,';',','),' ','')||']') j WHERE e.is_deleted=0
  UNION ALL
  SELECT j.value AS addr, '' AS name, e.sent_at FROM emails e,
    json_each('['||replace(replace(e.cc_emails,';',','),' ','')||']') j
    WHERE e.is_deleted=0 AND e.cc_emails IS NOT NULL AND e.cc_emails!=''
) WHERE addr!='' GROUP BY lower(addr)
```

  结果逐行套用与 upsert 相同的并入规则（collected 覆盖 frequency=freq）
- [ ] **Step 4: 通过** → **Step 5: Commit** `feat(contacts): 自动收集与存量回填`

**算法（与 spec §3.5 逐条对应，实现骨架）：**
