## 核心原则

1. **服务器为准原则**：任何同步冲突，以服务器当前状态为准。
2. **UID 追踪原则**：必须依赖 IMAP UID 而非序号进行邮件定位。
3. **元数据驱动原则**：利用 `UIDVALIDITY`、`UIDNEXT`、`HIGHESTMODSEQ` 实现增量同步，避免全量扫描。
4. **懒加载原则**：先同步信头，后同步正文，按需下载附件。
5. **本地优先原则**：用户操作先更新本地状态，再异步同步到服务器，确保UI响应速度。
6. **操作幂等原则**：所有同步操作设计为幂等，支持安全重试。
7. **分类同步原则**：个人邮箱和企业邮箱采用不同的同步策略和配置。

## 账号类型与同步策略

### 个人邮箱 vs 企业邮箱

| 维度 | 个人邮箱 | 企业邮箱 |
|------|----------|----------|
| **服务商检测** | 域名匹配（gmail.com等） | MX记录/Autodiscover检测 |
| **服务器配置** | 固定服务器地址 | 可自定义服务器地址 |
| **认证方式** | OAuth/密码/应用密码 | OAuth企业租户/域认证/SAML |
| **Token管理** | 标准OAuth刷新 | 租户感知的Token刷新 |
| **安全策略** | 基础安全 | 条件访问策略/MFA |
| **同步频率** | 默认5分钟 | 可配置，支持推送 |

### 服务商自动检测

```
用户输入邮箱 → 解析域名 → 匹配个人服务商列表
                          ↓ 未匹配
                     MX记录检测 → 指向Google → Google Workspace
                          ↓
                     指向Microsoft → Microsoft 365
                          ↓
                     其他 → 自定义企业邮箱
```

## 场景一：账号添加后的首次同步

**目标**：以最快速度让用户看到邮件列表，避免长时间等待。

### 1.1 建立连接与文件夹发现

```
连接 IMAP 服务器
    ↓
执行 LIST "" "*" 获取文件夹树
    ↓
识别系统文件夹：
    - 优先读取 ATTRIBUTES（如 \Sent、\Drafts）
    - 若无属性则根据名称猜测（如 "Sent"、"已发送"）
    - 支持多语言文件夹名称匹配
    ↓
在本地数据库初始化文件夹结构
```

### 1.2 关键元数据获取

对每个文件夹执行 `SELECT` 或 `STATUS`，获取并存储：

| 元数据 | 说明 | 用途 |
|--------|------|------|
| `UIDVALIDITY` | UID 有效性戳 | 检测邮箱重建 |
| `UIDNEXT` | 下一封邮件的 UID 预期值 | 增量同步起点 |
| `HIGHESTMODSEQ` | 最高修改序列号 | CONDSTORE增量同步 |

### 1.3 快速列表同步（骨架同步）

```imap
// 只拉取信头，不下载正文
UID FETCH 1:* (FLAGS BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE MESSAGE-ID)])
```

**优先级同步策略**：

| 优先级 | 文件夹 | 同步数量 | 说明 |
|--------|--------|----------|------|
| P0 | INBOX | 最新1000封 | 最重要的邮件 |
| P1 | Sent | 最新500封 | 已发送邮件 |
| P2 | Starred | 全部 | 星标邮件 |
| P3 | Drafts | 全部 | 草稿 |
| P4 | 其他文件夹 | 最新200封 | 按需加载 |
| 跳过 | Spam/Trash | 不同步 | 减少不必要数据 |

### 1.4 后台填充（内容同步）

```
用户浏览列表
    ↓
后台静默拉取：
    - 最近100封邮件的正文（BODY[]）
    - 计算邮件摘要和预览文本
    ↓
更旧邮件：
    - 用户点击查看时触发实时下载
    - 下载后缓存到本地
    - 支持附件懒加载
```

## 场景二：应用启动后的现有账号同步

**目标**：快速修正本地状态，同步离线期间的变更，处理多端冲突。

### 2.1 OAuth Token 检查与刷新

```
应用启动
    ↓
检查所有OAuth账号的Token状态
    ↓
计算剩余有效期 = expires_at - now
    ↓
有效期 < 5分钟？
    ├─ 是 → 执行Token刷新
    │        ↓
    │   刷新成功 → 更新本地Token
    │        ↓
    │   刷新失败 → 标记账号需要重新授权
    │                ↓
    │           通知用户
    └─ 否 → 继续
```

**企业账号Token刷新**：

```
企业账号检测
    ↓
获取租户ID（tenant_id）
    ↓
构建租户特定Token端点：
    https://login.microsoftonline.com/{tenant_id}/oauth2/v2.0/token
    ↓
执行刷新请求
    ↓
处理条件访问策略响应
```

### 2.2 上传本地离线操作

```
检查本地"待上传操作队列"
    ↓
逐一尝试在服务器执行：
    ├─ 成功 → 从队列移除，更新本地状态
    ├─ 失败（邮件不存在）→ 放弃该操作，等待同步阶段处理
    └─ 失败（文件夹不存在）→ 记录错误，提示用户
```

### 2.3 元数据校验（灾难恢复检查）

```
对比本地 UIDVALIDITY 与服务器当前值
    ↓
不一致？
    ├─ 是 → UIDVALIDITY 变更，执行毁灭性重建
    │        - 清空该文件夹本地数据
    │        - 重新执行"首次同步"逻辑
    └─ 否 → 继续增量同步
```

### 2.4 增量拉取新邮件

```imap
// 对比 UIDNEXT，拉取新邮件
UID FETCH <本地UIDNEXT>:* (FLAGS BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE)])
```

### 2.5 同步状态变更（处理多客户端修改）

**理想情况（支持 CONDSTORE 扩展）**：

```imap
// 利用 HIGHESTMODSEQ 获取变更
UID FETCH 1:* (FLAGS) (CHANGEDSINCE <本地MODSEQ>)
```

服务器仅返回自上次同步后状态发生变化的邮件。

**兜底情况（不支持 CONDSTORE）**：

```imap
// 对最近500封邮件执行 Flags 查询
UID FETCH 1:500 (FLAGS)
```

对比差异并更新本地状态。

## 场景三：应用在后台时定时获取新邮件

**目标**：在系统限制下感知新邮件，通知用户，保持数据新鲜度。

### 3.1 前台策略（应用打开时）

```
对 INBOX 发送 IDLE 命令
    ↓
保持 TCP 长连接
    ↓
服务器推送 EXISTS 消息
    ↓
立即结束 IDLE
    ↓
执行"增量拉取新邮件"逻辑
    ↓
重新进入 IDLE
```

**IDLE 连接管理**：

| 项目 | 配置 | 说明 |
|------|------|------|
| 最大IDLE时间 | 29分钟 | 避免服务器超时 |
| 心跳间隔 | 10分钟 | 发送NOOP保持连接 |
| 重连策略 | 指数退避 | 连接断开后自动重连 |

### 3.2 后台策略（应用切后台/息屏）

```
系统级推送优先（Gmail、Outlook API）
    ↓ 不支持
IMAP 轮询兜底
    ├─ Android: WorkManager
    ├─ iOS: Background Fetch
    └─ 桌面: 系统定时器
    ↓
间隔：15分钟
    ↓
执行轻量级 STATUS INBOX (UNSEEN)
    ↓
UNSEEN 数量对比：
    ├─ 增加 → 拉取新邮件头 → 发送本地通知
    └─ 减少 → 更新角标数字
```

### 3.3 新邮件通知机制

```
新邮件到达
    ↓
检查通知规则：
    ├─ 发件人白名单
    ├─ 主题关键词过滤
    ├─ 时间段限制
    └─ 文件夹过滤
    ↓
合并窗口（5秒）：
    ├─ 单封 → 显示: "发件人: 主题"
    ├─ 2-5封 → 显示: "您有N封新邮件，来自: 发件人列表"
    └─ >5封 → 显示: "您有N封新邮件，点击查看"
    ↓
发送系统通知
```

## 场景四：多客户端情况下的冲突处理

核心逻辑：**服务器状态覆盖本地**

### 4.1 冲突类型与处理逻辑

#### 状态冲突（已读/未读/星标）

| 本地状态 | 服务器状态 | 处理结果 |
|----------|------------|----------|
| 未读 | 已读 | 更新为已读 |
| 已读 | 未读 | 更新为未读 |
| 无星标 | 有星标 | 添加星标 |
| 有星标 | 无星标 | 移除星标 |

**处理逻辑**：服务器返回的状态直接覆盖本地。

#### 删除冲突

| 场景 | 处理方式 |
|------|----------|
| 本地有，服务器无 | 本地删除，不进回收站 |
| 本地删除中，服务器已移到垃圾箱 | 放弃本地删除，同步服务器状态 |
| 本地已删除，服务器仍存在 | 执行本地删除操作 |

#### 移动冲突

```
手机: A → B
电脑: A → C（先上传成功）
    ↓
手机上传失败（邮件不在A）
    ↓
放弃操作，同步服务器状态（邮件在C）
```

#### UIDVALIDITY 变更（毁灭性冲突）

```
检测到 UIDVALIDITY 变化
    ↓
保留本地旧数据（标记为"旧存档"）
    ↓
开启全新的全量同步流程
    ↓
同步完成后删除旧存档
```

### 4.2 冲突解决策略配置

```rust
pub enum ResolutionStrategy {
    /// 最后写入胜出（采用服务器状态）
    LastWriteWins,
    /// 本地优先（保留本地状态）
    LocalWins,
    /// 服务器优先（采用服务器状态）
    ServerWins,
    /// 用户决定（提示用户选择）
    UserDecision,
}

// 默认策略映射
fn default_strategy(conflict: ConflictType) -> ResolutionStrategy {
    match conflict {
        ConflictType::FlagConflict { .. } => ResolutionStrategy::ServerWins,
        ConflictType::LocationConflict { .. } => ResolutionStrategy::LastWriteWins,
        ConflictType::DeleteConflict { server_exists: false, .. } => ResolutionStrategy::ServerWins,
        _ => ResolutionStrategy::LocalWins,
    }
}
```

## 场景五：邮件操作同步流程

### 5.1 操作流程架构

```
用户操作 → 操作管理器 → 本地更新 → 操作队列 → 同步引擎 → IMAP服务器
                ↓                                    ↓
              UI更新                            同步结果
                                                   ↓
                                            更新本地状态
```

### 5.2 操作类型与IMAP命令映射

| 操作类型 | IMAP命令 | 幂等性 |
|----------|----------|--------|
| 标记已读 | `UID STORE {uid} +FLAGS (\Seen)` | 是 |
| 标记未读 | `UID STORE {uid} -FLAGS (\Seen)` | 是 |
| 添加星标 | `UID STORE {uid} +FLAGS (\Flagged)` | 是 |
| 移除星标 | `UID STORE {uid} -FLAGS (\Flagged)` | 是 |
| 移动邮件 | `UID MOVE {uid} {target-folder}` | 需检查 |
| 删除邮件 | `UID MOVE {uid} Trash` | 需检查 |
| 永久删除 | `UID STORE {uid} +FLAGS (\Deleted)` + `EXPUNGE` | 否 |

### 5.3 离线操作队列

```
离线模式检测
    ↓
操作加入本地队列
    ├─ 生成操作ID: {email_id}_{operation}_{timestamp}
    ├─ 记录操作前状态
    └─ 更新本地数据库
    ↓
用户可见变化
    ↓
恢复在线
    ↓
按时间顺序处理队列
    ├─ 去重优化
    ├─ 批量执行
    └─ 处理失败重试
```

### 5.4 操作队列数据结构

```sql
CREATE TABLE operation_queue (
    id INTEGER PRIMARY KEY,
    operation_id TEXT UNIQUE NOT NULL,
    account_id INTEGER NOT NULL,
    operation_type TEXT NOT NULL,
    resource_id INTEGER NOT NULL,
    payload TEXT,
    status TEXT DEFAULT 'pending',
    retry_count INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    synced_at INTEGER,
    error_message TEXT
);
```

## 场景六：附件下载管理

### 6.1 下载流程

```
用户点击下载附件
    ↓
检查本地缓存
    ├─ 命中 → 直接打开文件
    └─ 未命中 → 创建下载任务
                    ↓
              分块下载
                    ↓
              写入临时文件
                    ↓
              下载完成 → 移动到缓存目录
                    ↓
              记录下载状态
```

### 6.2 断点续传实现

```
下载任务开始
    ↓
记录已下载字节数
    ↓
网络中断
    ↓
恢复下载时：
    - 发送 FETCH BODY[{section}]<{offset}.{size}>
    - 追加到临时文件
```

### 6.3 缓存管理策略

| 策略 | 配置 | 说明 |
|------|------|------|
| 最大缓存大小 | 500MB | 超过时清理最旧文件 |
| 单文件大小限制 | 50MB | 超过提示用户 |
| 缓存过期时间 | 30天 | 未访问自动清理 |
| 清理策略 | LRU | 最少使用优先清理 |

## 场景七：Token 定期刷新机制

### 7.1 刷新策略

| 策略 | 触发条件 | 刷新时机 |
|------|----------|----------|
| 主动刷新 | 定时调度器 | Token过期前5分钟 |
| 被动刷新 | API调用失败 | Token过期或无效时 |
| 手动刷新 | 用户触发 | 用户主动请求 |

### 7.2 刷新调度流程

```
每分钟检查所有OAuth账号
    ↓
计算剩余有效期 = expires_at - now
    ↓
有效期 < 5分钟 且 不在刷新中？
    ├─ 是 → 加入刷新队列
    │        ↓
    │   获取刷新锁
    │        ↓
    │   执行刷新请求
    │        ↓
    │   成功 → 存储新Token，释放锁
    │   失败 → 重试计数+1
    │            ↓
    │       重试次数 < 3 → 安排重试
    │       重试次数 >= 3 → 通知用户重新授权
    └─ 否 → 跳过
```

### 7.3 企业账号刷新特殊处理

```
企业账号识别
    ↓
获取租户信息
    ├─ tenant_id
    └─ 企业域名
    ↓
构建租户特定Token端点
    ↓
处理条件访问策略响应
    ├─ 需要MFA → 引导用户完成认证
    └─ 设备策略 → 检查设备合规性
```

## 场景八：草稿同步机制

### 8.1 草稿保存策略

| 策略 | 触发条件 | 保存位置 |
|------|----------|----------|
| 自动保存 | 停止输入3秒 | 本地 + IMAP |
| 定时保存 | 每30秒 | 本地 |
| 手动保存 | 用户点击 | 本地 + IMAP |
| 退出保存 | 关闭编辑器 | 本地 + IMAP |

### 8.2 草稿IMAP同步流程

```
本地保存草稿
    ↓
检查在线状态
    ├─ 在线 → 同步到IMAP Drafts文件夹
    │          ↓
    │     APPEND Drafts {draft-mime}
    │          ↓
    │     获取服务器UID
    │          ↓
    │     更新本地草稿记录
    └─ 离线 → 标记为待同步
```

### 8.3 多设备草稿同步

```
定时同步Drafts文件夹
    ↓
对比本地与服务器的草稿列表
    ↓
检测变更：
    ├─ 服务器新增 → 下载到本地
    ├─ 服务器修改 → 更新本地内容
    ├─ 服务器删除 → 删除本地草稿
    └─ 本地新增 → 上传到服务器
    ↓
处理冲突：
    └─ 相同草稿ID，内容不同 → 采用服务器版本
```

## 性能优化策略

### 同步性能指标

| 指标 | 目标值 | 优化策略 |
|------|--------|----------|
| 首次同步1000封邮件 | < 60秒 | 批量获取、并发同步 |
| 增量同步10封新邮件 | < 2秒 | 仅获取变更 |
| 内存占用（空闲） | < 100MB | LRU缓存、流式处理 |
| 启动时间 | < 3秒 | 延迟加载、后台初始化 |

### 批量同步优化

```imap
// 批量获取邮件头（每批100封）
UID FETCH 1:100 (FLAGS BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE)])
UID FETCH 101:200 (FLAGS BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE)])
// ...
```

### 并发同步策略

```
文件夹优先级排序
    ↓
高优先级文件夹并发同步（最多5个）
    ↓
低优先级文件夹顺序同步
```

## 安全性考虑

### 通信安全

| 项目 | 要求 |
|------|------|
| TLS版本 | TLS 1.2+，优先TLS 1.3 |
| 证书验证 | 强制验证，支持证书钉扎 |
| 加密套件 | 仅使用强加密套件 |

### 凭证安全

| 凭证类型 | 存储方式 |
|----------|----------|
| 密码 | 系统Keyring（加密） |
| OAuth Token | 系统Keyring（加密） |
| 服务器配置 | 本地数据库（可加密） |

### 同步数据安全

```
敏感邮件内容
    ↓
本地数据库加密存储
    ↓
日志记录时自动脱敏
    ↓
缓存清理时安全删除
```

## 错误处理与重试策略

### 错误分类

| 错误类型 | 处理策略 | 重试次数 |
|----------|----------|----------|
| 网络超时 | 指数退避重试 | 5次 |
| 认证失败 | 不重试，通知用户 | 0次 |
| 服务暂时不可用 | 等待后重试 | 5次 |
| Token过期 | 刷新Token后重试 | 1次 |
| 邮件不存在 | 放弃操作 | 0次 |

### 重试间隔

```
重试间隔 = base_interval * 2^(retry_count)
base_interval = 1秒
max_interval = 60秒
```

| SELECT | 选择文件夹 | `SELECT INBOX` |
| STATUS | 获取文件夹状态 | `STATUS INBOX (UIDNEXT UIDVALIDITY MESSAGES UNSEEN)` |
| UID FETCH | 获取邮件 | `UID FETCH 1:* (FLAGS BODY.PEEK[HEADER])` |
| UID STORE | 修改标志 | `UID STORE 1 +FLAGS (\Seen)` |
| UID MOVE | 移动邮件 | `UID MOVE 1 Trash` |
| IDLE | 等待推送 | `IDLE` |
| APPEND | 添加邮件 | `APPEND Drafts {size} {flags}` |
