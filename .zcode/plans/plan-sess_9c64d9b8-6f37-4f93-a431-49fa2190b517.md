# MailView 右键菜单：文本 / 链接 / 图片

## Context

MailView（TextView 宿主 + 自有渲染内核）已接管正文渲染。本任务落地可行性文档 §5 的 P0 项：正文内右键上下文菜单——**文本**（复制/全选）、**链接**（打开/复制链接地址）、**图片**（复制图片/另存为）。当前正文右键无任何响应；列表行已有右键菜单先例（email_list.rs → gpui-kit `ContextMenuExt`），本任务复用同一基础设施与交互语言。

## 架构决策（基于侦察证据）

1. **菜单 UI**：复用 `ContextMenuExt::context_menu(builder)`（gpui-component 0.10 `menu/context_menu.rs`）——右键/触屏长按检测、anchored+deferred 定位、焦点恢复、点外消失全自动。builder 无命中参数 → 命中上下文须**预先捕获**。
2. **命中上下文跨帧载体**：builder 在 `window.defer` 的下一帧执行，`RenderCtx` 每帧重建不能承载 → 写入 **HtmlSelection**（每邮件交互状态，EmailDetailView 持有、全链路穿透、生命周期正确）：`SelState.right_hit: Option<SafeUrl>`——右键按下时由 SelectableText 写入（None=纯文本命中），左键按下时清除（浏览器语义：右键不破坏现有选区，左键开始新选区时失效）。
3. **文本组挂菜单**：`flush_text_group` 产出的 div 直接 `.context_menu(...)` 包裹（email_list 同款无 id 模式，同调用点共享状态 + hovered 守卫只让被按压的组弹菜单）。SelectableText 现有 MouseDown 监听加 **Right 分支**：`index_for_position` → `ranges.position(contains(ix))` 命中链接则 `selection.set_right_hit(Some(url))`，否则 `set_right_hit(None)`——即游标样式切换（email_html.rs:925）的既有判定式复用。
4. **图片挂菜单**：`render_loaded_image` 的 `img()` 包一层 `div().child(img).context_menu(builder)`——闭包在元素构造期直接捕获该图数据（无需命中检测），一处包裹覆盖块级/行内/表格内全部图片路径（共用此函数）。被拦截的远程图**占位框不挂菜单**（已有「加载图片」条，避免双入口）。
5. **图片字节三源归一**（新 helper `image_payload`）：
   - `ImageRef::DataUri { mime, bytes }` → 原始字节 + 按 mime 映射 `ImageFormat`（零重编码）
   - Cid / Remote → 手头只有 `Arc<RenderImage>`（BGRA，`as_bytes(0)`，gpui-pre assets.rs:72）→ BGRA→RGBA 交换 → `image` crate PNG 编码（png feature 已启用）
   - 产出 `(ImageFormat, Vec<u8>)`：剪贴板走 `ClipboardItem::new_image(&Image::from_bytes(fmt, bytes))`（platform.rs:3180/3447）；另存为直接写字节（DataUri 按 mime 定扩展名，重编码路径恒 .png，文件名 = alt 文本净化 || "image"）
6. **另存为流程**：沿用 attachments 先例（email_detail.rs:270-287）——`std::thread::spawn` 里 `rfd::FileDialog::set_file_name().save_file()` → 结果经 channel 回 `cx.spawn` → 后台线程写文件 → toast 成功/失败。

## 菜单项（沿用已批准的可行性文档 §4 规格）

| 目标 | 菜单项 | 行为 |
|---|---|---|
| 文本 | 复制（选中存在时可用，否则禁用） | `selection.selected_text()` → `write_to_clipboard(new_string)` + toast（复用 `email.selectionCopied` 流程） |
| 文本 | 全选 | 新 `HtmlSelection::select_all()`（anchor=(0,0) → head=(末组,末长)）+ `window.refresh()` |
| 链接 | 打开链接 | 命中 URL → 复用 `on_link` 回调（=open_safe_url） |
| 链接 | 复制链接地址 | `SafeUrl` 内串 → 剪贴板 + toast |
| 图片 | 复制图片 | `image_payload` → `ClipboardItem::new_image` + toast |
| 图片 | 另存为… | rfd 流程（上文 6） |

链接命中时优先链接菜单（不吃文本菜单）；图标用 IconName 既有项（ExternalLink/Link/Copy/Image/Save）。

## 验证

1. **单元**：`safeurl` 显示串；`image_payload` 对合成 RenderImage（synthetic_render_image 已有）产出非空 PNG 字节且可被 `image::load_from_memory` 解回。
2. **e2e**（沿 email_list 先例：PopupMenu 弹出属渲染层，动作走直测）：
   - `mail_menu_copy_link_writes_clipboard`：构造含链接文档 → 直调复制动作 helper → `cx.read_from_clipboard` 断言 URL 文本；
   - `mail_menu_select_all_selects_across_groups`：多组文档 → `select_all()` + 刷新 → `selected_text()` 含全部组文本、Ctrl+C 动作后剪贴板一致；
   - `mail_menu_builders_content`：右键命中链接态 vs 文本态分别构建菜单 → `PopupMenu::is_empty() == false`（菜单构建路径绿）。
   - 右键交互冒烟：`simulate_event(MouseDownEvent{button: Right, ..})` 打在链接文本 bounds 上不 panic、选区不被破坏（回归护栏）。
3. **全量**：`cargo test --workspace`（CI 同款门禁）。
4. **手工**：真机打开邮件——右键纯文本/链接/图片各出对应菜单；复制项落剪贴板可粘贴验证；另存为对话框出正确默认文件名；Esc/点外关菜单；右键不破坏既有划选。

## 明确不做（记录在案）

- 占位框（被拦截远程图）不挂菜单——「加载图片」条已是唯一入口
- 词级"复制光标处单词"（HtmlSelection 无词边界 API，浏览器亦无此默认项）
- 触屏长按菜单——ContextMenuExt 自带，但不在本任务测试矩阵
