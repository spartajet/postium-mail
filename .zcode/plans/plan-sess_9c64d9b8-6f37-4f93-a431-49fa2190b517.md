# MailView 实施计划：邮件正文渲染全面迁入 gpui-kit TextView（fork 补丁路线）

## Context

当前邮件正文 = `postium-html`（sanitize→IR）→ `email_html.rs` 递归构建 GPUI div 树（1638 行）。痛点：每帧整树重建、无虚拟滚动、文本组间无真行内混排。gpui-kit 0.10（2026-11-16 发布）的 TextView 提供块流编排、ListState 虚拟滚动、保留态 TextViewState，但其原生 html 管线无富样式 run 注入（文字色/字号丢失）、TableCell 无 colspan。

**用户决策**：① 全量 S0–S3；② 文本渲染与表格同采用自定义接管——不牺牲颜色/字号保真；③ fork 建公开仓库 spartajet/gpui-kit。

**架构定案（自定义块接管）**：MailView = Entity 包装 TextViewState；IR 序列化为**标记 HTML**（每块一个索引占位元素）；经 fork 补丁的 `html_block_parser` 把每个块认领为 `MarkdownNode{name:"mail-block", data:块索引}`；`html_block_renderer("mail-block")` 分派到我们自己的渲染器（从 email_html.rs 平移）。TextView 只当**块流宿主**（编排/虚拟滚动/保留态/无障碍文本管线），全部视觉与交互由我们现有代码渲染——**保真度零损失，探针体系原样存活**。未迁移块类型的文档自动回落旧渲染器（渐进切换）。

**前置条件**：PR #12（enhanced-textview→main）合并后，从 main 拉 `feat/mailview-renderer` 分支。

## 阶段计划

### S0 升级 gpui-kit 0.8 → 0.10（~0.5 天）
- `crates/postium-ui/Cargo.toml`：`gpui-kit`/`gpui-kit-assets` 0.8→0.10，dev-dep `gpui-pre` 0.3.9→0.3.12；postium-editor 同步。
- **先验证风险点**：`gpui-kit-markdown-editor`（git wabzqem，rev 31608fa，postium-editor 依赖）是否兼容 0.10——查其仓库有无 0.10 分支；不兼容则给该依赖也走 [patch] 或临时固定。
- 全量 `cargo build --workspace && cargo test --workspace`（CI 门禁=windows+ubuntu 双平台同款命令）。已知升级面：26 处 `use gpui_kit::*` glob、e2e_tests.rs 33 个 `#[gpui_pre::test]`。关键 API（shape_text/paint_image/text_system）已验证 0.3.9→0.3.12 签名稳定。
- 产出：0.10 vanilla 全绿提交。

### S0.5 fork + 补丁（~1 天）
- `gh repo fork longbridge/gpui-kit --clone`（spartajet）；从 `v0.10.0` tag 拉 `mailview-ext` 分支，**单 commit** 补丁：
  - `text_view.rs`：`pub fn html_block_parser<F>(F: Fn(&RcDom Node, attrs) -> Option<MarkdownNode>)` + `pub fn html_block_renderer(name, F: Fn(&MarkdownNode, &mut Window, &mut App) -> E)`——逐行对称复制 markdown 已有模式（markdown_ext.rs 的 MarkdownExtensions 容器复用/平行）。
  - `format/html.rs`：块级 parse 循环（`local_name!("table")` 分支附近）前插扩展询问点，经 NodeContext 线程穿透（仿 image_source 的传递方式）。
  - 补丁**零业务代码**；`MarkdownNode::new(name, text, data)` 已是 pub（markdown_ext.rs:121）。
- 推送 fork；根 `Cargo.toml` 加 `[patch.crates-io] gpui-base = { git = "https://github.com/spartajet/gpui-kit", branch = "mailview-ext" }`；全量测试。
- 同步向上游开 **draft PR**（有 markdown 对称先例，接收概率中高；合入即删 patch 两行）。

### S1 序列化器 + MailView 骨架 + 简单块接管（~2-3 天）
- **postium-html 新增 `src/serialize.rs`**：`serialize_marker_html(blocks: &[Block]) -> String`——每块产 `<div data-mb="{i}"></div>`（表格/引用等一律占位，内容不进 HTML）；纯函数，复用现有 10 组 fixture 做序列化快照测试（沿 `UPDATE_SNAPSHOTS` 模式）。S1 内先用单测验证 html5ever RcDom 保真回读 `data-mb` 属性（若属性被吞，退路：`<a name="mb-{i}">` 编码）。
- **postium-ui 新增 `views/mail_view.rs`**：
  - `MailView` Entity：持 `Entity<TextViewState>`（`TextView::html(id, marker_html)` + `html_block_parser/html_block_renderer` 挂接）；parser 闭包捕获 `Arc<Vec<BlockSpec>>`（BlockSpec = IR Block 克隆），渲染器经 `WeakEntity<MailView>` 每帧读取 ImageCtx/QuoteFold/HtmlSelection/theme 快照。
  - `stores/detail.rs` `CachedDoc` 扩展：序列化串 + `BlockSpec` 表 + `Entity<TextViewState>` 惰性缓存（浅/深双通道沿 dark_doc OnceLock 模式）。
  - 首批块渲染器（从 email_html.rs 平移）：Hr（389）、Heading、块级 Image（1027-1120 的三源分发+占位）、纯文本 Paragraph（725-804 文本组 + 807-980 SelectableText 原样复用）。
  - **渐进回落规则**：文档含未迁移块类型 → 整篇走旧 `render_html_document`（S1 末即在 email_detail.rs:502 切换主入口，fixture 覆盖的简单文档即刻走新路径）。
  - 探针：块渲染器内继续调 `when_probe`（html-root/html-hr/html-img/html-txt-*）——e2e 断言大面积存活。

### S2 富文本 runs + 链接 + 划选 + 引用折叠（~3-4 天）
- 富样式 runs（颜色/字号/粗斜删除线）进文本块渲染器：现有 InlineStyle→TextRun 映射代码平移，**保真不降级**（用户决策②）。
- 链接：SelectableText 命中→`on_link`→`open_safe_url` 语义不变；`link_tooltip`（0.10 新 API）加悬停真实 URL 预览（反钓鱼，增量功能）。
- 划选：HtmlSelection 保留，但**组注册表改为文档级预计算**（MailView 构建时由 IR 一次性算出 groups Vec，渲染期只报索引）——同时修掉现每帧注册的脆弱性，并为虚拟化下跨块选择铺路；Ctrl+C/Esc 沿 `EmailHtmlBody` key_context 动作不变。TextView 自身 `selectable(false)`（避免双选中系统）。
- 引用折叠：QuoteFold/`DetailStore.quote_expanded`/`toggle_quote` 状态机不动（detail.rs:86-94），引用块渲染器平移 email_html.rs:310-370 的折叠 UI。
- 图片门控：ImageCtx 三源缓存、`allow_remote_images` 流程、load-images 条（email_detail.rs:901-931）、`collect_remote_image_urls` 全部不动——我们自己的 img() 元素渲染，**不需要 image_source resolver**（无默认拉取隐私风险，因为图片不出现在序列化 HTML 里）。

### S3 MailTableCell 表格接管（~2-3 天）
- 新增 `views/mail_table.rs`：flex 表格渲染平移（email_html.rs:440-474 的 colspan→grow/width→basis 映射 + 已归一化网格的边框/列宽消费）；嵌套表格/单元格内任意块递归复用其他块渲染器。
- 表格操作：单元格右键/悬停菜单（复制单元格文本、整表转制表符文本进剪贴板）；`MarkdownNode.text` 填表格纯文本表示 → TextView 全选/复制管线自动含表格。
- e2e 的 colspan 宽度比例断言（e2e_tests.rs:2261-2279）作为迁移验收。

### S4 收尾切换与退役（~1-2 天）
- 回落规则删除（全类型已迁移）；滚动决策：v1 `scrollable(false)`（外层 overflow_y_scroll 不动、行为零变），v2 项：单 TextView `scrollable(true)` 启用 ListState 虚拟滚动（长邮件每帧收益），需配合预计算组表的跨块选择验证。
- e2e 全量过一遍并修余量（滚动容器语义、status bar 测试 2637）；删除 email_html.rs 中已无调用方的死代码（预计 SelectableText 保留、整树递归入口退役）；文档更新：MECHANICS.md、README、`docs/plans/2026-11-16-mailtextview-feasibility.md` 追加实施结论章。
- 提交拆分：每阶段独立 commit，S0/S0.5 各自成 PR-able。

## 验证方案

1. **每阶段**：`cargo build --workspace && cargo test --workspace`（= CI test.yml 门禁，双平台）。
2. **postium-html**：序列化快照测试（marker HTML 字节级对比，10 fixture 全覆盖）。
3. **e2e**（cargo test 内含，33 个 GPUI 测试）：重点集——`html_render_smoke`(1962)、`html_render_table_and_link`(2112, colspan 比例=表格迁移验收)、`html_images_blocked_until_allowed`(2828, 门控回归)、`html_email_display_keeps_status_bar`(2637, 布局回归)、`html_cache_same_id_new_content_renders`(2542, 缓存键回归)。
4. **手工冒烟**：真实账户打开典型邮件 ×10 fixture + aliyun 模板——深/浅色切换、引用折叠、图片拦截→放行→加载条消失、链接点击/悬停预览、Ctrl+C 划选复制、长邮件（long-zh-plain）滚动流畅度。
5. **补丁回归**：S0.5 后对比 vanilla 0.10 与 patch 版跑同一测试集，确认补丁零行为扰动。

## 风险与对策

- **markdown-editor git 依赖不兼容 0.10**（S0 卡点）：查 wabzqem 仓库 0.10 支持；否则同法 [patch] 或临时降级该组件功能。
- **补丁 rebase**：上游约每周发版；单 commit 纪律 + 插入点固定在 html.rs 块级 match，冲突面最小化；上游 PR 合入后移除 patch。
- **data-mb 属性被 html5ever 规范化**：S1 第一件事写回读单测验证；退路 `<a name>` 编码。
- **虚拟化×跨块选择**：v1 不开 scrollable 规避；预计算组表已为 v2 铺路。
- **上游拒收 PR**：长期养单 commit 小 fork（已接受）。
